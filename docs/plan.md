# Диктофон уроков: план

Статус: утверждён и выполнен, виджет работает. Дата: 19.10.2026. Исходные данные: `brief.md` (лежит в ветке `new-lesson-scenario`).

## Что проверено в этой сессии, до плана

Два рискованных места проверены на машине, чтобы план не был догадкой.

1. **Индикатор по каждому устройству.** `astats` поверх `amerge` даёт уровень отдельно по каналам обоих устройств, и это читается из stdout ffmpeg построчно, пока идёт запись. Проверка: 3 секунды, в выводе `lavfi.astats.1..4.RMS_level`, каналы 1 и 2 это микрофон (-59 дБ, шум комнаты), каналы 3 и 4 это стерео микшер (-90 дБ, то есть цифровая тишина, ничего не играло). Значит «звук идёт с обоих» показывается честно, а не домыслом.
2. **Остановка через `q` в stdin.** Из Python через `subprocess` с `CREATE_NO_WINDOW`: запись 5 секунд, запись байта `q`, процесс вышел сам за 0,61 с с кодом 0, файл 49 КБ, `volumedetect` показал `max_volume: -11.6 dB`. Убивать процесс не нужно.

Побочное: у dshow есть задержка старта около 1 секунды, при `sleep 5` длительность файла 4,02 с. На таймер это не влияет, но длительность файла будет чуть меньше показанного времени.

Список устройств сверен заново, служебные имена из брифа совпадают.

## Решения

| Вопрос | Решение | Почему |
|---|---|---|
| Язык и GUI | Python 3.14 + tkinter, один файл | Уже стоит, новых пакетов не нужно |
| Без консоли | Ярлык целит в `C:\Python314\pythonw.exe`, расширение `.pyw`, ffmpeg порождается с `CREATE_NO_WINDOW` | Чёрного окна нет ни у виджета, ни у ffmpeg |
| Имена устройств | Служебные `@device_cm_...`, константами в начале файла | Русские имена ломаются, см. бриф |
| Папка записей | Абсолютный путь `...\vibecoding\Lessons records`, переопределяется переменной `LESSON_RECORDS_DIR` | Скрипт может запускаться из worktree, относительный путь писал бы не туда |
| Остановка | `q` в stdin, ждём 15 с | Проверено выше, файл цел |
| Закрытие окна во время записи | Перехват крестика: сначала корректная остановка, потом выход | Иначе ffmpeg осиротеет, `q` отправить будет некому, файл битый |

## Окно

Около 280x160, `-topmost`, без разворачивания.

```
  ┌──────────────────────────────┐
  │  ●  00:14:32                 │
  │  ┌────────────────────────┐  │
  │  │      Запись / Стоп     │  │
  │  └────────────────────────┘  │
  │  Микрофон    ▓▓▓▓▓▓░░░░  ●   │
  │  Компьютер   ▓▓▓░░░░░░░  ●   │
  │  19.10.2026 21.40.m4a        │
  └──────────────────────────────┘
```

- Таймер от старта процесса, `ММ:СС`, после часа `Ч:ММ:СС`.
- Две полосы уровня, по строке на устройство, шкала от -60 дБ до 0.
- Точка рядом с полосой: зелёная, если за последние 3 секунды уровень был выше -45 дБ, иначе серая. Порог выбран между цифровой тишиной (-90) и шумом комнаты (-59), то есть зелёное означает реальный звук, а не живое устройство.
- Нижняя строка: имя файла, который пишется. После остановки держит имя и длительность.
- Если ffmpeg упал сам (устройство занято, например держит OBS или Voicemeeter), строка краснеет и показывает последние строки его stderr.

## Имя файла и перезапись

- Формат `ДД.ММ.ГГГГ ЧЧ.ММ.m4a` по времени старта.
- Если файл с таким именем есть (второй старт в ту же минуту), к имени добавляется ` (2)`, ` (3)` и так далее. Плюс ffmpeg запускается с `-n`, то есть даже при промахе в проверке он откажется писать, а не затрёт.

## Параметры записи

Те же, что в брифе: `amix=inputs=2:duration=longest`, `aac`, 96 кбит/с. Поверх добавляется ветка измерения уровней, она в файл не попадает (`anullsink`).

## Ярлык

`make_shortcut.ps1` создаёт `Диктофон уроков.lnk` на рабочем столе: цель `C:\Python314\pythonw.exe`, аргумент путь к `recorder.pyw`, рабочая папка `tools\lesson-recorder`, иконка системная (своей рисовать не будем).

Путь в ярлыке будет указывать на основной чекаут (`...\vibecoding\tools\lesson-recorder\recorder.pyw`), а не на worktree, то есть ярлык заработает после влития ветки. Проверку 15 секунд я прогоню запуском из worktree напрямую.

## Проверка, как просил

1. Запуск виджета, запись 15 секунд с речью в микрофон и звуком из браузера или плеера, остановка кнопкой.
2. Файл открывается, `ffmpeg -i файл -af volumedetect -f null -` показывает звук.
3. Отдельно проверяю, что на индикаторах за время записи загорались оба устройства.
4. Повторный старт в ту же минуту: прошлый файл на месте, новый пишется как ` (2)`.
5. Закрытие крестиком во время записи: предлагает остановить, файл цел.

## Вне объёма

- Расшифровка по кнопке после остановки. В брифе помечена как «по желанию». Whisper стоит, но это отдельная история: занимает процессор почти целиком и требует индикации прогресса. Предложу отдельной задачей.
- Голоса учеников через Bluetooth или Voicemeeter. Стерео микшер ловит только Realtek, это ограничение железа, виджет тут ничего не исправит. В README напишу, как заметить проблему: индикатор «Компьютер» не загорается во время созвона.
