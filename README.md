# Диктофон уроков

Мини-виджет поверх окон: пишет мой микрофон и звук компьютера (голоса учеников) в один файл m4a, разводя их по каналам, и после остановки сам расшифровывает запись в текст рядом с аудио. Нужен для логов проведённых занятий.

Windows, Python 3.14 с tkinter, ffmpeg в PATH. Самой записи ничего кроме стандартной библиотеки не нужно. Расшифровке нужен `faster-whisper`, см. раздел «Расшифровка».

## Запуск

- Ярлык «Диктофон уроков» на рабочем столе.
- Или вручную: `C:\Python314\pythonw.exe recorder.pyw`.

Ярлык создаётся один раз, из папки проекта:

```powershell
powershell -ExecutionPolicy Bypass -File make_shortcut.ps1
```

Скрипт прописывает в ярлык тот путь, из которого его запустили. Переехал проект, значит прогнать ещё раз.

`make_shortcut.ps1` хранится в UTF-8 с BOM, и так и должен храниться. PowerShell 5.1 читает `.ps1` без BOM как ANSI, русские строки в нём превращаются в мусор и скрипт падает на разборе.

## Что в окне

- Таймер и мигающая красная точка, пока идёт запись.
- Кнопка «Запись» и «Стоп».
- Две полосы уровня: «Микрофон» и «Компьютер». Точка справа зелёная, если за последние 3 секунды с устройства шёл звук громче -45 дБ. Серая точка означает тишину, а не сломанное устройство: шум пустой комнаты это примерно -59 дБ, цифровая тишина -90 дБ.
- Нижняя строка: имя файла во время записи, после остановки имя, длительность и размер.
- Под ней строка расшифровки, пока она идёт: процент и остаток времени, затем имя готового текстового файла. Появляется сама после остановки и прячется, когда начинается новая запись.

Уровни появляются не сразу, а через 2-3 секунды после старта: столько занимает запуск dshow.

## Куда пишутся записи

Папка задана в `recorder.pyw` константой `DEFAULT_RECORDS_DIR` и указывает не внутрь этого репозитория, а туда, где лежат материалы курса:

```
C:\Users\Daniyar\Desktop\Work\Projects\Courses\vibecoding\Lessons records
```

Так сделано намеренно: записи живут рядом с занятиями, а код отдельно. Переопределяется переменной окружения `LESSON_RECORDS_DIR`.

- Имя `ДД.ММ.ГГГГ ЧЧ.ММ.m4a` по времени старта. Второй старт в ту же минуту даёт ` (2)`, ` (3)`. Плюс ffmpeg запускается с `-n`, то есть существующий файл не перезапишется ни при каком промахе.
- AAC 96 кбит/с, около 80 МБ за 2 часа.
- Стерео, но не для звука: левый канал это микрофон, правый звук компьютера. Расшифровка по каналу понимает, кто говорит.
- Рядом появляется `.txt` с тем же именем. Пока он дописывается, на диске лежит `.txt.part`: недоделанный текст не выглядит готовым.
- Запись подписывает себя в метаданных (`comment`), чтобы расшифровка знала раскладку наверняка.

## Остановка

Только кнопкой «Стоп» или через крестик с подтверждением. Виджет посылает ffmpeg `q` в stdin и ждёт, пока тот сам закроет файл. Если убить процесс грубо, заголовок m4a не допишется и файл не откроется. Поэтому закрытие окна во время записи перехвачено и спрашивает подтверждение.

Если ffmpeg не ответил на `q` за 20 секунд, виджет его всё же завершит и честно напишет в статусе, что файл может быть повреждён.

## Если «Компьютер» молчит во время созвона

«Стерео микшер» ловит только то, что идёт через звуковую карту Realtek. Если созвон звучит в Bluetooth-наушниках или уехал в Voicemeeter, голосов учеников в записи не будет, и индикатор это сразу покажет: полоса «Компьютер» останется пустой. Лечится переключением вывода звука созвона на Realtek перед началом урока.

## Если сменилась звуковая карта

Список устройств:

```powershell
ffmpeg -list_devices true -f dshow -i dummy
```

Взять из вывода строки `Alternative name` для микрофона и стерео микшера и подставить в начало `recorder.pyw` в `MIC_DEVICE` и `MIX_DEVICE`, оставив префикс `audio=`. Русские имена устройств использовать нельзя: при передаче в ffmpeg теряется первая буква и он не находит устройство.

## Расшифровка

Запускается сама, после удачной остановки записи, отдельным процессом с пониженным приоритетом и без своего окна. Кнопка «Запись» при этом работает: записать новый урок важнее, чем дорасшифровать прошлый. Закрытие виджета расшифровку не убивает, она допишет текст сама, а её ход останется в `%TEMP%\lesson-recorder\<имя записи>.log`.

На лету, во время урока, расшифровки нет и не будет: причины в [docs/tasks/live-transcription/plan.md](docs/tasks/live-transcription/plan.md).

Руками, на любой файл, в том числе на старый:

```powershell
python transcribe.py "C:\Users\Daniyar\Desktop\Work\Projects\Courses\vibecoding\Lessons records\19.10.2026 20.26.m4a"
```

Ключи: `--model` (по умолчанию `large-v3-turbo`), `--language` (по умолчанию `ru`), `--layout split|mixed` на случай, если раскладка определилась неверно.

Движок `faster-whisper` стоит в пользовательских пакетах того же `C:\Python314`, поэтому запускать надо обычным `python`, без изоляции. **`av` нужен ровно 16.x.** `pip install faster-whisper` тянет самый новый, а на 17 и выше любая расшифровка падает с `TypeError: open() got an unexpected keyword argument 'metadata_errors'`. Лечится `pip install "av==16.1.0"`.

Сколько ждать: платим за время речи, а не за длину файла, потому что тишину выбрасывает VAD. Замерено 20.10.2026: канал с речью идёт примерно в 1,2 раза медленнее своей речи, а канал учеников, который большую часть урока молчит, обходится в десятую часть первого. Урок на 2 часа это около 1 часа 55 минут счёта.

Текст первого урока по новой теме стоит прочитать глазами: модели подсказан список терминов курса через `initial_prompt`, и она иногда вставляет подсказанное слово там, где его не было.

Смешанная копия, если нужно послушать урок одним потоком:

```powershell
ffmpeg -i "19.10.2026 20.26.m4a" -ac 1 "19.10.2026 20.26 микс.m4a"
```

## Как сделаны индикаторы

Запись и измерение уровней это один процесс ffmpeg. Входы раздваиваются: одна ветка сводит каждое устройство в моно и кладёт их в разные каналы файла через `join`, вторая идёт в `amerge`, где оба устройства склеиваются в четыре канала, `astats` считает по каждому RMS, а `ametadata=print` печатает его в лог ffmpeg четыре раза в секунду. Виджет читает stderr процесса и разбирает строки `lavfi.astats.N.RMS_level`.

В ветке файла обязателен `apad` на каждом моно-потоке. У `join`, в отличие от прежнего `amix`, нет `duration=longest`: он заканчивается по самому короткому входу, и отвал одного dshow-устройства обрезал бы запись урока на этом месте. Проверено 20.10.2026: входы 3 и 8 секунд без `apad` дают файл на 3 секунды.

Печатать метаданные в файл или в stdout (`ametadata=print:file=-`) нельзя: вывод буферизуется и приходит одной пачкой только при выходе, за 8 секунд записи не приходит ни строки. Проверено 19.10.2026.
